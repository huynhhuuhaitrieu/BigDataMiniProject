    Detector playground

    Runs the same MetricEngine used inside Spark, in-process, on one NAB file. It also replays the file in micro-batches with a JSON state round trip (what the checkpoint stores) and compares the result with a single pass.

    Các tham số nghĩa là gì?
    FractionPhần đầu dữ liệu dùng để "học" mức bình thường (0.15 = 15% đầu). Static lấy trung bình và độ lệch chuẩn từ đoạn này. Các điểm này không được chấm.
    ToleranceDùng khi lịch sử phẳng hẳn (độ lệch chuẩn ≈ 0, không chia được): giá trị chỉ bị coi là lạ khi lệch hơn mức này.
    History NRolling so mỗi điểm với N điểm ngay trước nó. Dữ liệu CloudWatch đo 5 phút/lần, nên 100 điểm ≈ 8 giờ.
    Min periodsRolling cần có ít nhất chừng này điểm trước đó mới bắt đầu chấm (giai đoạn "warmup").
    ThresholdMức lạ |z| ≥ ngưỡng thì báo động. Tăng ngưỡng → ít báo nhầm hơn nhưng dễ bỏ sót sự cố.
    Micro-batchChia dữ liệu thành các lô cỡ này, lưu rồi khôi phục state giữa các lô giống Spark checkpoint. Kết quả phải giống hệt chạy một lần.

    Thử nhanh: đổi Threshold 3 → 4, hoặc History N 100 → 300, rồi so cột False alerts. Chọn ec2_cpu_utilization_c6585a.csv (không có vùng sự cố) để thấy mọi báo động đều là báo nhầm.

    Correctness checks

    Each scenario feeds hand-made events to MetricEngine and shows what came out. These mirror the contract tests in tests/.
